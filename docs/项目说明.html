BioCheck
把证据准确地写进答案

潘倩负责的，是最终生成质量：让模型按证据写，检查它实际写出了什么，发现问题后做有依据的修订。研究从真实的论文摘要和临床登记材料开始。

维护人：潘倩　｜　代码位置：zktest / BioCheck　｜　更新：2026年10月30日

第一次看这份文档：先读下面的工作流程，再看真实例子，最后照“开始动手”里的命令跑一次。论文阅读和实验设计放在后半部分，不必一口气读完。

课题建议名称：面向生物医药研判的证据约束生成与条件一致性核验方法研究。这个名字覆盖写前约束、成稿检查和修订评价，具体创新点要由实验结果确定。

01 / 工作位置

你接手的是成稿前后的质量控制

用户问“这条管线是否值得继续研究”，李明洋先组织调查，拿到资料、对象关系和证据评价。BioCheck接收这批材料，参与写作并检查成稿。问答、研报、自动发现后的调查结论，都可以复用同一套方法。

谁负责交给下游什么和潘的关系
徐子雯原始资料、清洗文本、来源和版本BioCheck必须能回读这次所用的文字。发现缺页、错版或材料缺失，反馈给资料与调查环节。
唐蔚雯药物、靶点、疾病、企业及研究之间的对应关系帮助判断两个名字是否同一对象、两篇材料是否同一研究。当前代码没有假定图谱已全部接通。
李明洋问题、调查结果、可用材料、调用安排和总预算由他决定何时调用BioCheck、补查什么，以及怎样把结果返回用户。
汪鑫怡证据质量、机制支持程度及适用范围评价研究证据本身能说明多少；其结果可作为输入，潘仍须核对成稿有没有夸大或改变含义。
潘倩表达计划、成稿问题、原文定位、修订稿和待核项对实际输出文字负责。原文分段编号只是定位工具，不承担全库资料抽取。

潘怎样干预LLM

  1. 1 / 接收接收这次的材料

    问题、原文、来源版本；已有的证据评价可随包传入。

  2. 2 / 规划约束准备表达的内容

    明确研究、人群、组别、指标、时间和允许的结论强度。

  3. 3 / 生成真正调用模型写稿

    把原文和表达计划一起送入模型，取得完整候选稿。

  4. 4 / 核验检查实际写出的稿

    重新读取原文和成稿；核验者看不到作者计划和自评。

  5. 5 / 修订只改定位到的问题段

    其他段落由程序原样保留；修后重新检查整稿，最多一次。

  6. 6 / 返回返回文字及真实状态

    同时给出依据、未解决问题和覆盖缺口，由调度方决定补查或交付。

这里的关键是第3步和第4步相连：潘的方法会作用于实际生成的答案。只把一个提示词包交给上游，无法知道最终稿是否真的遵守；只检查上游结构化数据，也发现不了写作时新增的错误。

这些方法继续在一个Python项目内维护，独立实验可以直接调用DeepSeek。雷达当前开发代码已通过共享适配器加载BioCheck的generate、verify、revise，并由雷达统一执行模型调用和计入预算；本项目没有增加独立微服务。方法接入与正式服务验收分别记录，具体范围见下面的接入说明。
02 / 看真实材料

数字都是真的，也可能写错

DREAMM-2摘要给出两组剂量与多个疗效指标。把总生存期14.0个月挪到无进展生存期的位置，数字仍在原文里，结论却已经变了。判断时要连着看“哪项研究、哪一组、什么指标、什么时间”。

字段2.5 mg/kg组3.4 mg/kg组
总缓解率 ORR32%35%
中位无进展生存期 PFS2.8个月3.9个月
中位总生存期 OS15.3个月14.0个月

资料来自徐现有Fabric中的 DREAMM-2最终分析摘要（PMID 37622738）。此处展示用于核验的研究记录，不把摘要中的描述直接升级成临床决策。

以下内容读取本次实际实验记录；切换例子不会调用模型。受控错误是根据真实原文人工改错的句子，原文材料真实，错误句并非论文原句。

六类问题分别检查什么
检查方向要问的问题常见例子
对象与研究（OBJ）这个结果到底属于谁？把同一研究的两次分析当成两项独立研究；把两组结果交换。
数值与单位（NUM）数值、单位、分母、计算能对上吗？32%写成32人；3个百分点写成30个百分点。
时间（TIME）随访、截止、治疗周期有没有混用？把中位随访9.5个月写成中位PFS。
适用条件（COND）原文限定的人群和设计是否保留？重度经治患者写成初治；摘要未说明设计，却补成回顾性。
结论强度（STR）成稿比证据多说了什么？相关性写成因果；10例治疗序列观察写成已证明最优方案。
引用（REF）这句话所引的材料真支持它吗？两个正确结论的引用对调；片段存在却不包含所述事实。

一条陈述可以有多个标签。缺少证据和已有反证要分开：前者需要补查，后者需要纠正。模型给出的标签仍须通过样本评价检验。

03 / 已有结果与问题

代码已经跑真实材料，效果仍要独立评价

本次从Fabric读取78条真实记录，选用其中9份原文组成8个问题包：剂量比较、药物经济学、药物暴露与疗效、治疗序列、不良事件、临床前机制、试验登记和跨研究比较。8份是论文摘要，1份是临床登记原件。问题包由本项目按原文准备。上述开发实验使用徐的只读接口；当时没有接入汪的机制评价和唐的完整图谱。治疗序列那份记录还附有更正链接，正式标注前应补齐更正内容；本轮只评价所取文本版本的表达一致性，没有把来源自身正确性一并证明。

表中“完成”只表示程序返回了结果。Token为接口已返回的用量，包含缓存输入等，不代表账单金额。各轮均保留原始记录。推理核验开发轮完成4项后，因内部片段编号干扰写作而停止：另4项已启动但未完成、48项尚未启动。未完成项还有160,570个已返回Token及4次用量未知调用，不计入表内完成任务用量。最终改为作者看完整原文、只引用来源编号，核验内部保留片段定位。这些都在开发材料上开展，不能当作独立测试成绩。各轮还改过提示与推理模式，不能直接把轮次通过率差异解释成某一算法的增益。

当前使用DeepSeek V4 Pro：规划和写作采用非推理模式，核验和修订采用high推理模式。最终56项商业任务共158次调用、约130.85万Token；自然稿任务耗时中位数约308秒，短句任务约36秒。

原始56项中50项程序完成、6项失败。随后只修复了核验原句定位失败的处理方式：5项返回待核或保留已确认问题；另1项修后回执缺少覆盖评价，仍明确报错。离线复查逐次核对阶段、系统提示和输入一致后复用原回执，新增API调用为0。这是鲁棒性修正，不是语义效果提升。

先看教训，再看数字

  • 第一轮52项中17项程序失败。大多是核验模型用省略号拼接“引文”，或对“本摘要未提供某项结果”不给原文位置。后来改为原文片段编号，由程序取回文字；材料缺省另记录整份检查范围。
  • 第二轮的16条错误句全部被标出、16条正确句全部通过，但自然稿仍有漏检。长稿中出现“双臂写成单臂”“擅加回顾性设计”“未提及检验写成未进行检验”。这说明短句成绩不能代替真实成稿质量。
  • 修订也会制造错误。一次修订把keratopathy写成“角膜炎”；原文支持的是角膜病变这个更宽的概念。新版本启用了推理核验并重查这些原始长稿，仍须保留未解决例子。部分长稿的单次核验已实测耗时约145—221秒；耗时和成本也是研究结果。
读表方法：下面各格依次是“机器PASS / 待核REVIEW / 明确问题FAIL / 程序ERROR”。机器PASS表示本次检查没发现问题，不能拿它当独立人工正确率。修订后的PASS也不自动说明没有新增错误。

运行记录在哪里，怎样重新统计

完整原文在data/，各轮模型公开回执和结果在runs/。这些目录留在zktest本机、由Git忽略。仓库保存题目、原文版本编号、控制句和汇总，不提交密钥及整批运行原文。本次选段失败样例单独保存了两份公开临床登记的固定节选与公开回执，便于离线复现。

python3 -m app.summary runs/reprocessed-v4/results.json runs/experiment-v4/results.json runs/regressions-v3/results.json

调用记录保留实际请求、公开输出、模型名、结束状态、耗时和用量，不保存隐藏推理。原文来自当前取得的记录，这次没有做历史回测。

新发现：事实写对了，核验却选错了原文

2026年10月30日回查雷达真实验收记录时，发现 U1 的第0条陈述说“NCT05020236 的登记摘要称 elranatamab 为 BCMA-CD3 双特异性抗体”。事实及记录级引用正确，模型也返回了 PASS，但它只选了 qef6ac51e879c:S1 [0,1200)。这段没有该事实；真正支持在 S2 [1200,2157)，对应短语从第1844个字符开始。

原核验看到了整份材料，可能从其他段落读懂事实，却报错了支持位置。程序检查了位置存在、引用对应，仍没有保证该段文字支持这句话。U1 第2条陈述还选了另一来源的 S13，它能支持药物类别和双靶向描述，不能连带判错。

后两行各调用一次与原验收相同的 deepseek-flash，共 7,179 token。两次公开回执均保留，没有重试到通过。这是一个已知失败例的处理验证，尚不能证明方法的总体准确率、漏检率或论文创新。

固定原文、原模型回执、来源版本与人工发现保存在 evaluation/selected_support_case.json；两次新回执和用量在 evaluation/selected_support_results.json。运行下面的离线测试即可复现，不调用 API。默认 verify 仍能重放原 PASS，新复核须由调用方明确启用。

python3 -m unittest discover -s tests -v
仍需研究：新增复核依旧由模型判断语义，逐字摘录只校验出处，不证明摘录真正支持结论。它只审已标支持的事实及其所选片段，不负责发现所有漏拆陈述、核验“整份材料未提供某信息”、检索缺失资料或自动重选。原有“keratopathy 被写成角膜炎仍获 PASS”的漏检记录继续保留；本轮未重新实验这类错误。
04 / 开始动手

先跑一个问题，再看三个函数

源码在zktest：/home/zk_test/zk_projects/BioCheck。使用Python 3.10及以上，全部是标准库，不用先安装Agent框架。模型配置已放在项目私有.env；日常无需把密钥抄进代码。

第一步：看一次真实生成和核验

cd /home/zk_test/zk_projects/BioCheck
python3 -m app.cli data/cases/dreamm.json --output runs/pan-first --method bound

运行后打开runs/pan-first/result.json和answer.txt。先找generated.draft看初稿，再看initial_review，最后比较revision和final_review。同名输出已存在时换一个目录名，避免把旧实验盖掉。

第二步：只检查自己写的一段话

把待查中文文字保存为draft.txt，保留形如[E1]的引用。来源编号要与输入材料包一致。

python3 -m app.cli data/cases/dreamm.json --check draft.txt --output runs/pan-check

--check只检查，不自动改稿。模型调用失败会报错并留下调用记录；不得把未返回的核验写成通过。

第三步：重取徐的相同版本材料

python3 -m app.prepare --output data/my-materials
python3 -m app.experiment --cases data/my-materials/cases.json --output runs/my-comparison --workers 3

prepare通过既有只读接口取指定记录，按题目里的版本核对后生成材料包。这个命令已经实测，重取的8个问题包与本次用料完全一致。若原版本不在当前接口中，命令会指出缺哪份；不要悄悄换新版本后沿用旧标签。

不用网络取数时，以及怎样限制调用
python3 -m app.prepare --records data/fabric_records.json --output data/from-existing
python3 -m app.cli data/cases/dreamm.json --output runs/limited --method bound --max-calls 5
python3 -m unittest discover -s tests -v

--max-calls限制本次CLI模型调用次数，额度不足会停下；当前没有独立金额预算平台。调用方仍负责总预算。独立实验的并发数由--workers设置。

重复陈述的定位约定（2026年10月29日修复）

核验回执中的span必须能唯一定位。重复原句可以同时给出span_start与span_end，也可以把相应引用一起包含在唯一span中。提供位置时严格核对切片；没有位置且原句出现多次时返回待核，不猜第几次，不默认取第一次。该约定同时适用于claims和issues。

generate、verify、revise、run的调用形式保持不变，原有回执字段保留。verify补充段内位置；verification_errors非空表示核验回执有未解决的问题，调用方必须保留已检查原稿与完整回执，跳过自动修订。即使status为FAIL，也要检查这个字段：已确认错误和定位不明确可以同时存在。

雷达共用用例在evaluation/citation_location_cases.json，包含输入、模型回执、预期状态，以及待核和混合状态的完整返回样例。例子中“第一次[E1]、第二次[E2]”在明确第二位置后为FAIL；只有同文span时为REVIEW且不自动修改。正确重复则可通过。

让雷达单独复核所选证据

新增普通函数 audit_support(packet, review, call, targets=None)。输入为固定证据包和 verify 的完整回执；可用 targets=[("U1", 0), ("U1", 2)] 指定陈述，序号从0开始。不传 targets 时检查全部符合条件的事实。材料缺省等判断跳过；没有可审条目返回 NOT_RUN，不花一次调用。

from app.core import audit_support

# call 由雷达提供，继续使用它的预算和公开回执记录。
audit = audit_support(packet, review, call, targets=[("U1", 0), ("U1", 2)])
# 原 review、原 PASS、原稿均保留；audit 单独存储。
# audit 为 REVIEW：人工检查所选原文，必要时重选，再单独复核。
# 不把 audit 传给 revise，不因核验器选错段自动改稿。

每次有效复核只调用一次 call("support_audit", instruction, {"claims": [...]})。每条输入只含该陈述、待核段落上下文、固定来源身份和该条所选原文；不含旧结论及其理由，不送未选的原文。上下文用于理解代词，不能作为事实证据。多段合起来足够支持即可。

模型回执格式如下；supported 必须摘录本条所选片段内的逐字文字。缺项、重复、未知目标、无效摘录进入 verification_errors，返回 REVIEW。请求失败直接报错，不自动重试。

{"checks": [{"unit_id": "U1", "claim_index": 0,
  "verdict": "supported",
  "reason": "说明具体支持关系",
  "support": [{"evidence_id": "E1", "segment_id": "S2", "quote": "逐字原文"}]}]}

复核结果中的 checks 保存本次送审范围及所选原文，original_status 保留旧状态。新的 status 为 PASS、REVIEW 或 NOT_RUN，仅适用于这些送审条目。not_supported 表示所选片段不足以支持，不能转换成“正文事实错误”。原回执已有 verification_errors 时直接待核，不再请求模型。

雷达适配：本次没有改变 generate、verify、revise、run 的参数和默认调用次数，也没有修改雷达源码。当前雷达适配器尚无 support_audit 阶段；启用前须映射新阶段（建议名 biocheck_support_audit）、预留一次调用及 token、保存两份回执，并把 REVIEW 交给证据复核。人工重选后再次复核是另一次明确计费调用。原有 verification_errors 不自动修订的条件仍须保留。

05 / 研究要做深的地方

论文要回答方法为什么有效

“先规划、再生成、再核验”已有大量工作。把这些步骤接起来能交付工程，但论文要找到具体难点，提出可检验的方法差异，并解释什么时候有效、什么时候失败。建议围绕下面三个问题组织研究。

问题一：写作前绑住条件，能少写错吗？

普通计划写“比较两组疗效”；绑定计划还写明研究、人群、剂量、终点、时间及推断范围。假设是后者能减少“真实数字放错对象”和“限制条件丢失”。现有代码已经有这两个版本。

对照：使用相同问题、证据、模型和相同两次规划/生成调用，比较普通计划与绑定计划；直接生成另作成本参考。去掉绑定中的时间或组别约束，观察对应错误是否增加。

看什么：初稿错误陈述比例、重要条件保留率、问题覆盖程度、输出长度和用量。不能靠减少回答内容来获得更高正确率。

问题二：核验者有没有替错误稿辩护？

前期开发实验已有实证：“双臂”被解释成“可视为单臂”，摘要的沉默被解释成研究没做。这类错很适合研究。比较只拆孤立短句、保留上下文的原文陈述，以及明确保留条件的检查，分析拆分是否改掉了原意。

对照：在同一批原稿上比较整体检查、细粒度陈述检查、条件感知检查；预先标出研究、组别、人群、时间、否定及医学术语范围。保留正确复杂句，专门测误报。

看什么：发现率、误报率、无法判断率、问题定位、证据支持程度。当前原文分段和段落覆盖是程序保证，所有子陈述是否被穷尽仍要人工抽查。特别单列方法学分析与建议：例如“开放标签设计可能引入偏倚”，它未逐字出现在研究摘要中，也不能直接算医学事实错。需要先约定允许的分析前提，再评价推断是否合理。

问题三：修对一处，会不会又写错另一处？

目前只允许修改问题段，段外文字按字符保留。这是工程上的保护。问题段里仍可能新造错误，例如把病变名称翻译得过于具体；重新核验也可能漏掉。

对照：同一份问题稿比较不修订、全文重写、局部修订。每种只给一次机会，记录所有调用。全文重写对照尚需潘补充，不能先声称局部修订一定更优。

看什么：原问题实际修复比例、新错误数、正确事实删除数、关键内容保留率、成本。把“补上引用”与“改正医学事实”分别统计。

一个值得下功夫的方向：跨语言医学表达的范围保持。英文术语在中文成稿里变窄、变强，通用核验容易认为意思差不多。可研究源术语与成稿术语的对齐及专门评价，复用唐或既有权威术语资源；不要在潘的项目另建一套全库实体系统。

怎么建立可信实验

  1. 先建立20份独立材料包。覆盖临床试验、观察研究、机制研究、登记原件和经济评价。不要只围绕同一个药物家族扩写变体。
  2. 把自然稿和改错句分别收集。自然稿用来测实际错误；成对改错用来诊断具体能力。标注每条陈述、必要条件、原文位置、支持或反对理由，无法确定也要有标记。
  3. 按研究和共享原文划分数据。同一试验的多篇论文、同一原稿的改写版本放在同一组，防止一边调方法一边测试近似样本。
  4. 形成开发集后，再扩大独立测试。建议先做到60份以上独立材料包、约120个实际问题，再按错误覆盖和标注质量决定规模。最终测试前停止调提示；至少由两人独立标注争议样本，再由导师或专业人员裁定。
  5. 评测不靠本系统自打分。独立人工评价作为主要依据，第二模型可辅助；报告所有失败、代价和适用范围，不把同源变体当独立样本。

本次10条回归例已经用于开发，应留在开发集中。以后即使全过，也不能拿来替代未见过的材料评价。
